# Checkbox — port notes

Deliberate departures from the reference's published prop contract, and the
component-specific decisions behind them. The reference `.d.ts` is authoritative
for prop names, unions and defaults; everything below overrules it on purpose.
**Do not "fix" one back.**

The rules that hold for _every_ component — the styling contract, semantic
tokens, status roles, snap-don't-extend, the no-`pill` directive, theming, the
accessibility floor and the standing port decisions — live in
`.agents/skills/tia-design-system/SKILL.md`. Read that first; this file is only
what is true of Checkbox alone.

## Card rows

`variant="card"` adds a bordered label row with a medium radius and a 44px minimum height.
It requires a label or description; a bare box keeps its existing rendering.
The default variant stays unchanged. Caller classes still reach the element that draws the outer border.

The outer label mirrors the bound state because Bits UI puts `data-state` on the checkbox button.
Checked cards use scoped `color-mix`: primary 9% with surface for the fill, and primary 38% with transparent for the border.
These token mixes are an explicit exception to utility-only colour rules. They need no new tokens and follow both themes.
Mixed state keeps its dash; error state keeps its red box, label, and accessible invalid state.
Card mode disables the box's colour transition. Its check still draws when selected.

`locked` changes presentation only when the card is disabled. It adds a decorative lock, background-subtle, and border-muted.
The disabled box remains at half opacity. The caller supplies the reason through `description`; the lock does not change its accessible name.
Temporary disabling without `locked` keeps the selected surface and adds no ownership icon.

Card rows also take an optional `trailing` Snippet. It renders at the far edge of the row for local status or price copy.
Builder uses it for per-product prices and the owned-row message, so the Checkbox API owns that slot instead of page markup around it.
The label block and the trailing slot both shrink from their content width, so on a narrow row they share the room and the trailing copy wraps.
A fixed `flex-1` label beside a `shrink-0` trailing slot left the label 9px at 320px, and its text ran under the note.
Trailing copy that must stay on one line, such as a price, sets `whitespace-nowrap` itself.

### Why this is not Card

The card row is a label that toggles the primitive button. Card renders a div, not the label this control requires.
