# Button — port notes

Deliberate departures from the reference's published prop contract, and the
component-specific decisions behind them. The reference `.d.ts` is authoritative
for prop names, unions and defaults; everything below overrules it on purpose.
**Do not "fix" one back.**

The rules that hold for _every_ component — the styling contract, semantic
tokens, status roles, snap-don't-extend, the no-`pill` directive, theming, the
accessibility floor and the standing port decisions — live in
`.agents/skills/tia-design-system/SKILL.md`. Read that first; this file is only
what is true of Button alone.

| Contract                                                            | Built as                                            | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `size: sm｜md｜lg｜icon｜pill`                                      | `size: sm｜md｜lg｜xl｜icon`                        | the reference's `pill` bundled a 52px box with a full radius; since the base radius is now full for every size, only the box was left, and it became `xl`                                                                                                                                                                                                                                                                                                            |
| `variant: default｜accent｜destructive｜outline｜ghost｜link`       | adds `success`                                      | the reference has no clickable success tone; checkout's period button needs one. It is the status tint pair, `bg-success-light` with `text-success-strong`, on a `border-success/35` edge that goes solid `border-success` on hover and press. The fill and ink do not step: no `--success-hover` token exists, and the edge carries the state. Like `ghost`, it does not lift, because it reads as an inline offer rather than a raised control                     |
| `variant.secondary`                                                 | removed                                             | the reference's own `Button.jsx` has no such variant — it was a leftover in this repo's pre-port component, and it had zero committed call sites                                                                                                                                                                                                                                                                                                                     |
| destructive hover `#b00000`, press `#9a0000`                        | both on `--destructive-hover`, which _is_ `#b00000` | the hover value is the reference's exactly; only the press snaps up onto it, rather than a second token existing for one variant's one state — which is what `accent` already does, pressing onto `--secondary-hover`. This replaced `bg-destructive/90` and `/80`: a slash modifier composites against the backdrop instead of naming a colour, so the hover came out _lighter_ than the resting fill on the light canvas, the opposite of what the reference draws |
| named transition properties, motion and colour on different easings | `button-motion` utility in the shared CSS layer     | Transform, translate, scale and shadow use 200ms `ease-out-soft`; background uses 200ms `ease-in-out`. Colour, border and opacity retain their 200ms soft transition. Low selector specificity lets caller transition classes override the utility. Hover lift and press scaling apply only without reduced motion. Variants, colours and disabled behavior stay unchanged.                                                                                          |
